دليل تكامل التاجر

أنشئ مفتاحاً من الإعدادات ← ربط متجري عبر API. يُعرض مرة واحدة. احفظه في أسرار خادم موقعك، ويمكن إلغاؤه من التطبيق. لا تستخدم مفتاح موظف أو مفتاح Convex إداري.

عنوان الخدمة يزوّدك به مسؤول المشروع حسب البيئة، ثم المسار /merchant/v1/. بيئة التطوير مستقلة عن الإنتاج.

أرسل الترويسة Authorization: Bearer YOUR_SECRET_KEY. لا تضع المفتاح في الرابط أو في JavaScript عام.

  • GET products: المنتجات والأسعار والمخزون المسموح للتاجر.
  • GET categories: التصنيفات.
  • POST orders: إنشاء طلب يخص صاحب المفتاح؛ يتطلب صلاحية إنشاء الطلبات.

لإنشاء الطلب أرسل ترويسة Idempotency-Key بقيمة مستقرة فريدة من 8–60 حرفاً إنكليزياً أو رقماً أو شرطة. أعد نفس المفتاح عند إعادة المحاولة حتى لا يتكرر الطلب. الحد الحالي 100 طلب في يوم بغداد لكل مفتاح.

{
 "customerName": "مشتري تجريبي",
 "phone": "07000000000",
 "province": "PROVINCE_ID",
 "region": "المنطقة",
 "address": "تفاصيل العنوان",
 "items": [{"product":"PRODUCT_ID","qty":1,"salePrice":20000}],
 "returnGuarantee": false,
 "shippingFromProfit": false
}

الخادم يتحقق من هوية صاحب المفتاح والمخزون وحدود السعر والمحافظة. لا ترسل مجموعاً أو رصيداً أو هوية تاجر محسوبة عندك. عند الاستجابة غير المؤكدة أعد المحاولة بالمفتاح نفسه. الإلغاء أو تعديل الحالات ليسا متاحين عبر هذا الإصدار من API.

النجاح يعيد رقم الطلب وتفاصيله. الأخطاء: 401 مفتاح غير صالح أو صلاحية غير كافية، 400 بيانات غير صالحة، 429 تجاوز حد الاستخدام. الاستجابة لا تعني وصول البضاعة أو قبول دفع مالي.
